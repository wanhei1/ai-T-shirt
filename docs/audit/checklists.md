## 一、架构图与代码不一致清单

| # | 架构图假设 | 代码实际情况 | 是否一致 | 严重度 | 修复建议 |
|---|-----------|-------------|---------|--------|---------|
| 1 | 支付由支付宝回调自动确认 | 实际是用户扫二维码后手动点击"我已支付"，调用 `createPaymentIntent` 记录意向，无支付宝服务端回调验证 | ❌ 不一致 | 🔴 High | 接入支付宝当面付 API，由支付宝服务端回调 `/payments/webhook/:channel` 确认支付状态 |
| 2 | AI 生图结果持久化到数据库 | Worker 结果写入 Redis/内存，**未入库**。Redis 重启或 worker 重启后结果丢失 | ❌ 不一致 | 🔴 High | 生成结果写入 `all_designs` 或新增 `ai_generated_images` 表 |
| 3 | 图片存储使用对象存储 | `canvas_front/back` 以 base64 文本直接存 PostgreSQL `text` 列，单张图 2-5MB | ❌ 不一致 | 🔴 High | 迁移到 MinIO/S3，数据库只存 URL |
| 4 | ComfyUI 为内部服务 | ComfyUI 监听 `127.0.0.1:8188`（仅本地），但前端 `.env` 暴露了公网 IP `82.157.19.21:8188`，用户可直连 | ⚠️ 部分一致 | 🟡 Med | 前端不应暴露 ComfyUI 地址，所有 AI 请求必须走后端代理 |
| 5 | 后端统一认证 | 前端 Next.js API 路由 (`/api/generate-image`, `/api/virtual-tryon`) 绕过后端 Express，直接调用 ComfyUI，**无认证** | ❌ 不一致 | 🔴 Critical | 删除前端 Next.js API 代理路由，所有 AI 请求走后端 `/api/generate` |
| 6 | Worker 消费 RabbitMQ | Worker 确实消费 RabbitMQ，但 RabbitMQ 监听在 `0.0.0.0:5672`（公网可达），任何人可连入 | ⚠️ 部分一致 | 🔴 High | RabbitMQ 绑定 `127.0.0.1` |
| 7 | PostgreSQL 为唯一数据库 | 服务器同时运行 MySQL（3306/3307）和 Elasticsearch（9200），但项目未使用 | ✅ 一致（多余服务） | 🟢 Low | 确认是否需要，不需要则关闭节省资源 |
| 8 | Redis 用于缓存+Job State | Redis 确认用于缓存和 Job State，但默认无密码 | ⚠️ 部分一致 | 🟡 Med | 设置 Redis 密码 |
| 9 | 订单状态机 | 架构图假设完整状态机，实际 `orders.status` 字段无 CHECK 约束，前端可设置任意状态值 | ❌ 不一致 | 🟡 Med | 添加数据库 CHECK 约束或后端状态机校验 |
| 10 | CDN/对象存储用于静态资源 | Next.js 静态资源直接由 PM2 的 `next serve` 提供，无 CDN | ❌ 不一致 | 🟡 Med | 部署到 Vercel 或加 CDN |

## 二、服务器端口暴露清单

> 实测数据来源：`ss -tlnp` (2026-05-06)

| 22 | SSH | `0.0.0.0` | ✅ 是 | ✅ 是（需限制 IP） | 暴力破解风险 |

| 443 | Caddy HTTPS | `*` | ✅ 是 | ✅ 是 | — |

| 8189 | Express API | `*` | ✅ 是 | ❌ **否** | 应仅通过 Caddy 反代访问 |
| 5432 | PostgreSQL | `127.0.0.1` | ❌ 否 | ❌ 否 | ✅ 安全 |
| 6379 | Redis | `127.0.0.1` | ❌ 否 | ❌ 否 | ✅ 安全（但无密码） |
| 5672 | RabbitMQ | `0.0.0.0` | ✅ **是** | ❌ **否** | 🔴 公网可连入，默认密码 |

| 9200 | Elasticsearch | `0.0.0.0` | ✅ **是** | ❌ **否** | 🔴 数据泄露风险 |
| 5601 | Kibana | `0.0.0.0` | ✅ **是** | ❌ **否** | 🔴 管理面板公网暴露 |
| 3307 | MySQL | `0.0.0.0` | ✅ 是 | ❌ **否** | 数据库暴露 |
| 8080 | 未知服务 | `0.0.0.0` | ✅ 是 | ❓ 需确认 | — |
| 8000 | 未知服务 | `0.0.0.0` | ✅ 是 | ❓ 需确认 | — |
| 8190 | Python 进程 | `0.0.0.0` | ✅ 是 | ❓ 需确认 | — |
| 8848 | 未知服务 | `0.0.0.0` | ✅ 是 | ❓ 需确认 | — |
| 9848 | 未知服务 | `0.0.0.0` | ✅ 是 | ❓ 需确认 | — |

### 端口暴露总结

| 状态 | 数量 | 端口 |
|------|------|------|
| ✅ 安全（仅本地） | 4 | 5432, 6379, 8188, 3306 |
| ❌ 应关闭公网 | **8** | 3000, 8189, 5672, 15672, 9200, 5601, 3307, 8501 |
| ✅ 正确公网 | 3 | 22, 80, 443 |
| ❓ 需确认 | 5 | 8080, 8000, 8190, 8848, 9848 |

**🔴 严重问题：RabbitMQ (5672) + 管理面板 (15672) + Elasticsearch (9200) + Kibana (5601) 公网暴露且无认证**
