## 四、图片存储与传输链路优化

**状态**：✅ 代码改造完成 | ✅ 旧数据迁移完成 | ✅ 新任务端到端验证通过

**背景**：Redis 存储 base64 图片导致内存膨胀（263MB）、轮询响应体 1-2MB、手机端加载慢。

### 改动清单

| Phase | 内容 | 文件 | 状态 |
|-------|------|------|------|
| 1 | Worker 输出改为文件 URL | `workers.ts` | ✅ |
| 2 | 入队前 input 图片存磁盘 | `routes/index.ts` | ✅ |
| 3 | Next.js /assets 反向代理 | `next.config.mjs` | ✅ |
| 4 | Redis TTL 24h → 7 天 | `state-repository.ts` | ✅ |
| 5 | 轮询接口返回 URL | `routes/index.ts` | ✅ |
| 6 | 前端兼容新旧格式 | `ai-generator.tsx`, `editor/page.tsx`, `preview/page.tsx` | ✅ |
| 7 | 旧数据迁移 | `migrate-redis-base64.ts` | ✅ |

### DB 变更
```sql
CREATE TABLE virtual_tryon_results (
    id SERIAL PRIMARY KEY,
    job_id VARCHAR(64) UNIQUE NOT NULL,
    result_image_url TEXT NOT NULL,
    cloth_type VARCHAR(16),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE ai_image_results (
    id SERIAL PRIMARY KEY,
    job_id VARCHAR(64) UNIQUE NOT NULL,
    result_image_url TEXT NOT NULL,
    prompt TEXT,
    style VARCHAR(32),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 旧数据迁移结果
```
扫描: 136 keys
清理: 124 条 base64（删除 result 字段，DB 无对应记录）
错误: 0
Redis 内存: 263MB → 137MB (↓ 48%)
```

### 修复的构建问题
- **ArrayBuffer 类型不兼容**：`getImage()` 返回 `ArrayBuffer`，`storeBuffer()` 期望 `Buffer`。在 worker 中添加 `Buffer.from()` 转换。
- **dist 未更新**：源码修改后未重新编译，Worker 跑旧代码。重新 `npx tsc` 构建后解决。
